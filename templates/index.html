METRICS SPECIFICATION

ABOUT THE METRICS

A quick guide to the indicators used to assess technical debt.

01 🔄

Cyclomatic Complexity

Measures the number of independent paths through the code. Higher complexity generally means code is harder to test, maintain, and understand.

02 📋

Code Duplication

Percentage of repeated logic across the codebase. High duplication increases maintenance overhead and the risk of inconsistent bug fixes.

03 🧪

Test Coverage

Proportion of code exercised by automated tests. Low test coverage leaves critical paths vulnerable to undetected regressions.

04 🔗

Coupling (CBO)

Measures how heavily classes or modules depend on each other. Tightly coupled code is fragile and difficult to isolate or refactor.

05 🧩

Cohesion Deficit (LCOM)

Identifies classes whose methods don't operate on shared data. High LCOM points to "God classes" that violate the Single Responsibility Principle.

06 ⚡

Code Churn

Tracks how frequently files are modified. High churn combined with high complexity is one of the strongest predictors of technical debt.

07 🐛

Past Defects

Historical bug count associated with a module. Areas with repeated past defects are prone to recurrent instability.

08 🛡️

Security Vulnerabilities

Known security weaknesses or risky coding patterns. Vulnerabilities represent high-risk debt requiring immediate remediation.
